# 完整decoder段迁移：条件带宽估算

2026-10-14研究摘要。目标方案把两个全attention层及中间GDN层连成零基7–11完整段，以减少跨机交接次数。该方案与attention-only不同，还迁移稠密Q8C投影、MLP及相应权重计算。

## 已有结果与估算分开

[原五层组件实验](segment-validation-five-layer.zh.md)测得CUDA40.271872ms、Mac4.081718ms，差约36.19ms；投影占CUDA计算97.63%。后续[B2线性优化](linear-kernels-q8.zh.md)改善2.2–2.3倍，按比例推算五层约18.3ms，**尚非整段复测**。

| 容量项 | 静态算术 |
| --- | ---: |
| 五层Q8C权重 | 1.877411GiB |
| 两个attention层KV，262,144 tokens | 1.015625GiB |
| 上述两项合计 | 约2.893GiB |
| 两层KV＋权重，1,048,576 tokens | 约5.940GiB |

这些不是实际峰值或准入通过。还需计GDN、scratch、运行时、传输、副本和储备；原研究5GiB设备硬预算不能把“2.893<5”直接当成可分配证明。[KV容量表](../data/kv-memory-table.json)列出算术前提。

## 带宽论证的适用前提

用五层文件体积2,015,854,592B除以Mac五层4.081718ms，得到约494GB/s的**等效字节/时间比**。它不是Mac实测DRAM事务速率。

假设每次B8计算必须从4060显存读取这批权重一次，没有额外压缩或足够缓存复用，并以同机纯流读probe的264GB/s作为持续传输参照，则仅这些字节就约需7.6ms，高于这次Mac组件4.08ms。这个理想化估算说明：**在当前硬件、批量、权重流量假设和基线下，为了提速而迁移整段缺少支持。**

它不是通用物理不可能证明。更大batch、其他硬件、缓存命中、权重复用/表示变化、不同Mac负载和重叠策略都会改变前提。probe包含缓存/访问模式影响，也不是所有kernel的严格带宽上界；494GB/s与264GB/s不能被当成两个精确硬件能力常数。

## 通信不能偷换实验

[协议客户端实验](blackbox-timing-split.zh.md)记录了另一个attention-only协议条件下0.867ms的“传输＋客户端残余”。它不是本五层段的通信实测，不能据此宣布段的瓶颈100%在计算或完整段RPC已知。五层原轮TCP/echo为0帧。

## 决策价值

- **速度目标**：目前保留attention/KV路线，完整段需先证明投影集成和交接改善；不按未测收益扩大范围。
- **容量目标**：可以研究以延迟换内存，但要实测Mac实体backing释放。原五层解除1.877GiB映射只观察到80KiB RSS下降，不能宣称已腾出同等RAM。
- **新实验门槛**：同输入单层/整段计时、完整状态生命周期、实际通信、资源峰值和清理均须独立验证。任何容量/速度收益都应以新测量报告。

原完整段和线性实验工具未随包分发，见[来源与证据范围](provenance.md)。
