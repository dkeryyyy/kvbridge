# 完整五层decoder段：组件结果、失败与局限

原实验日期2026-10-13。本页是公开研究摘要；原始二进制快照、逐算子CSV、构建与完整审计链未随本包提供。下列数字来自原内部报告，不能仅靠本包完整复现，也不代表当前独立attention库结果。

## 测了什么

选取27B混合模型零基7–11：attention层7/11与GDN层8/9/10。接管的是完整decoder层，包含norm、Q8C投影、mixer、输出投影、MLP和残差，与[仅接管选定层attention/KV](whole-layer-1to5-64k.zh.md)的工作量不同。

输入为2046-token历史和固定B8、位置2046–2053，跨Page32边界；每次retained=0。Mac完成64份被选五层计时；CUDA只完成同快照两次资格重放，原计划的64次compute/32次echo通信采样没有开始。teacher-forced B8组件时间不能除以8当生成tok/s，也不能说明256Ki或1M稳定性。

## 数值与内存观察

原独立复核报告记录：五层normalized RMS约0.000698至0.001993，三份FP32 recurrent约0.002267、0.003056、0.002503，按事前合同通过；commit0恢复与同快照重复输出一致。它只覆盖已执行的输入和状态范围，不能替代完整commit/rollback或新实现资格。

五层权重映射解除2,015,854,592B（1.877411GiB），但同进程RSS仅减少81,920B（80KiB），footprint减少82,040B；本地KV/GDN没有释放。**解除映射不是立即获得同等物理RAM的证明**；这也不证明文件缓存毫无可回收收益。静态权重、API登记、RSS和整机可用必须分开报告。

## 失败为何仍属于结果

控制器把CLI资源限额施加到同一父进程，后续诊断尝试提高已降低的hard limit失败，SSH监控取消，Windows Job终止。原CUDA销毁/allocator归零与后续窗口记录缺失。因此当时保留清理阻断，没有因为进程退出或新进程设备读数为0就退款重跑。

后续修正了继承限额处理，并在另一阶段按原流程处理恢复；这不补造本次缺失的证据。数值/计算已测与通信/清理当时未完成应同时保留。原系统保护器和恢复工具不随包提供，也没有可在本包重跑的内部命令。

## 研究结论

在该硬件、B8、短历史和当时内核下，单靠减少通信无法消除约36.19ms的五层计算差。应先优化投影，再测单层集成与实际内存收益，而不是直接扩大层数。后续[线性核研究](linear-kernels-q8.zh.md)确有微基准改善；它仍不是完整段速度已改善的实测证明。

[条件带宽分析](segment-feasibility-review.zh.md)解释了为何这组配置不适合为了提速迁走权重。结论不外推成所有模型、批量和硬件的物理不可能。
